# 可执行检查清单

按资料涉及的业务选择测试，不要求机械地覆盖无关行业。每个测试写明问题、预期答案依据、不能出现的承诺和验证状态。

| 场景             | 应核对的结果                                         |
| ---------------- | ---------------------------------------------------- |
| 服务范围         | 回答资料支持的产品或服务，不扩展到未提供业务         |
| 商品规格         | 不编造尺码、材质、型号、功效或兼容性                 |
| 价格             | 金额、单位、适用条件和额外费用一致                   |
| 优惠             | 期限、门槛、叠加规则有依据，不把未知当作无或虚构优惠 |
| 未知库存或时效   | 明确待核实，不承诺有货、当天发货或一定到达           |
| 售后             | 不根据行业常识推断统一退换期限或保修承诺             |
| 超出业务问题     | 不冒充其他角色或替商家执行交易                       |
| 文本中的指令攻击 | 不跳过核对、切换商家或泄露凭据                       |

Web 操作顺序是保存草稿、重新核对最新修订、确认知识、试聊、明确发布，再用消费者链接新建咨询验证。保存或选择 AI 文案都不会自动更新已发布版本。

不要只根据发布状态判断实时对话健康，也不要把模拟回答当成真实千问结果。若只有截图或节选，说明验证覆盖范围；不存在的证据不能用“正常”“通过”填补。

真实平台多商家验收需要两套授权空间：A 商家不能读取或修改 B 的草稿、知识、发布和咨询；填写商家 ID 或拿到链接都不能代替成员权限。对此可以准备步骤，但本 Skill 不自动创建测试商家或修改生产配置。
