# 客服草稿字段

与本项目 Web 草稿字段对应；这些名称不是远程 API 授权参数。Web 当前没有 JSON 一键导入入口，文字需复制到对应字段后保存。

| 字段                    | 名称             | 最大长度 | 撰写重点                                             |
| ----------------------- | ---------------- | -------- | ---------------------------------------------------- |
| displayName             | 客服名称         | 200      | 店铺或品牌可辨识，不能冒充人工或官方认证             |
| industry                | 细分行业         | 128      | 主营品类、服务对象或交付形态，避免只写“电商”“服务业” |
| businessScope           | 业务范围         | 2000     | 可以回答的事项、业务限制；时间和地区需依据           |
| materialsSummary        | 商品或服务资料   | 4000     | 商品名称、参数、用途、条件、FAQ，保留来源和待确认项  |
| pricingSummary          | 价格与条件       | 4000     | 金额、单位、适用商品与条件、额外费用；未知如实说明   |
| promotionSummary        | 优惠与售卖策略   | 4000     | 门槛、有效期、叠加条件；“没有”必须由用户明确说明     |
| welcomeMessage          | 欢迎语           | 500      | 明确 AI 身份，引导业务问题，不承诺未提供的能力       |
| insufficientInfoMessage | 资料不足时的回复 | 500      | 说明待核实，已有公开联系方式才可引用                 |

前三个单行字段及欢迎语、资料不足回复保持单行；业务范围、商品资料、价格和优惠可以分段。长度是 Web 保存约束，不是要求把文案写满。客服名称目前仅在创建时设置，已创建客服的资料修订没有改名入口。

整套资料默认按上述顺序展示，并在末尾列出仍需补充的事实。不要把待确认事实混入已确定的报价或活动规则。
