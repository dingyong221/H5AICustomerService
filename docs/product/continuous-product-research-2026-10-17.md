# 中小商家 AI 客服竞品研究与持续改善路线

查阅日期：2026 年 10 月 17 日。产品定位：让缺少技术能力的中小商家完成创建客服、日常使用、持续改善三个连续阶段。第一轮优先解决“看见一条答不好的咨询，却不知道怎么把它修好并验证上线”的断点。

## 研究范围和证据等级

选择四个海外、三个国内产品：Chatbase、Tidio Lyro 是直接的自助客服参考；Intercom Fin、腾讯企点是客服运营闭环参考；晓多是电商垂直参考；Zendesk 是偏企业的间接参考；FastGPT 是低代码知识问答邻接参考，不把它当作开箱即用的商家接待系统。

下表的产品能力来自已打开的官方公开产品页、帮助和计费文档，标记为“官方说明”；公开页面的导航、表单说明与价格展示是“公开可观察”。未注册或登录这些产品的付费后台，未导入真实商家材料，未实测其回答质量。借鉴结论和适用性是本项目的产品判断，不采用厂商宣传的自动化比例作为实测结果。

## 七个产品的流程和借鉴

### Chatbase

官方流程是添加网站、文件、文字和问答资料，编写规则，在 Playground 测试，再部署渠道。其公开产品总览展示资料、指令、测试、会话和分析的连贯导航。[产品总览](https://www.chatbase.co/features/product-overview)

最值得借鉴的是 Activity 内的 Revise Answer：保留原问题与原回答，让商家填写期望答案，保存为问答资料；已有问答可直接回到对应资料。这把“发现错误”与“修改知识”放在同一条操作路径上。[Activity 和纠正答案](https://www.chatbase.co/docs/user-guides/chatbot/activity)

商业化按套餐及 message credits 分层，资料建议、高级分析等另有套餐限制；credits 不是消费者会话数。当前年付展示 Hobby 为 32 美元每月、700 credits，Standard 为 120 美元每月、4,000 credits，Pro 为 400 美元每月、15,000 credits；这不是对本项目定价的建议。[定价](https://www.chatbase.co/pricing)

适配判断：适合学习短路径纠错和同题复测。多模型选择、复杂动作与流程编辑器不是我们首轮重点，置信度也不能替代事实核验。

### Tidio Lyro

官方帮助将 Knowledge、Playground、Channels、Handoff 和 Hub 连起来：未知问题可补答案；人工在线和离线分别处理；复杂或敏感问题可转交或建立保留原会话的工单。人工出口是业务流程，不只是一句安抚话术。[Lyro 操作指南](https://help.tidio.com/hc/en-us/articles/9003475527196-Lyro-the-conversational-AI-agent)

Suggestions 汇集实时聊天中的待补问题，提供次数、意图、最近时间和来源会话；商家审核并填写答案后保存为问答，也可以忽略。官方说明目前不适用于邮件工单。[待补知识建议](https://help.tidio.com/hc/en-us/articles/24182486548892-Lyro-Suggestions)

商业化分别配置客服工作台、Lyro 和 Flows。首次 50 次 Lyro 会话为账户生命周期额度，不是每月免费额度；当前年付展示独立 Lyro 从 32.50 美元每月、50 次会话起。常规 Lyro 会话只要求至少一次 AI 回复，并非确认解决。[计费及口径](https://www.tidio.com/pricing/)

适配判断：最接近中小电商的运营方式。先学待补问题和可信人工出口，不立即复制完整坐席、订单动作和复杂额度体系。

### Intercom Fin

官方流程包括 Train、Test、Deploy：从历史、CSV 或手工问题测试，人工评 Good 或 Poor 并记录原因，连人工交接一起测试；配置受众、结束条件和满意度后再扩大上线范围。相应聊天部署文档还有公开帮助文章数量条件，不能推断成零资料一键开通。[部署和测试](https://www.intercom.com/help/en/articles/8286630-deploy-fin-ai-agent-over-chat)

Recommendations 区分内容缺口、业务数据缺口和执行动作缺口，并关联原会话。这一点直接影响产品决策：不知道退货政策可以补资料；查订单和取消订单需要系统接口或人工，不能全部伪装成 FAQ 修复。该推荐能力有 Pro add-on 条件。[改善建议](https://www.intercom.com/help/en/articles/11390088-optimize-fin-instantly-with-the-help-of-ai)

Fin 与 Intercom 组合涉及席位和使用量，接已有 Helpdesk 则按 Outcome 并有承诺条件。Outcome 包含确认或推定解决以及特定完成后交接等口径，不能直接作为真实满意解决率。[计费定义](https://www.intercom.com/help/en/articles/8344190-pricing-faqs)

适配判断：学习问题分类、固定问题复测、人工判断；先不用付费自动主题分析和复杂受众编排。

### Zendesk AI agents

官方创建流程要求绑定品牌和知识来源、填写业务信息、配置欢迎、负反馈和兜底升级方式，测试后再激活渠道。不能回答与消费者认为没帮助都需要后续处理。[创建流程](https://support.zendesk.com/hc/en-us/articles/10488757995034-Creating-an-AI-agent-to-automatically-resolve-customer-issues)

Automation potential 使用最近 90 天已解决或关闭工单分析覆盖与知识缺口；可由缺口生成文章草稿，再审核权限、发布。这是自动化潜力预测，不是线上实际成功率；新商家可能没有足够数据。[知识缺口到文章草稿](https://support.zendesk.com/hc/en-us/articles/9877546283930-Viewing-and-using-the-automation-potential-report-to-create-or-enhance-AI-agents)

商业化为人工席位套餐加 AI 使用量。当前年付 Suite Team 展示 55 美元每席位每月；不能拿更低的 Support Team 入门价声称包含同等聊天体系。[定价](https://www.zendesk.com/pricing/)

适配判断：学习草稿、审核、发布的边界和负反馈出口，不依赖大规模历史工单才让小商家开始改善。

### 腾讯企点客服大模型机器人

官方产品覆盖官网、公众号、小程序等咨询渠道，并说明售前、售后、知识解析、工作流与业务接口能力；首次开通配置的易用性仍需真实后台体验。[产品页](https://cloud.tencent.com/product/cslr)

官方动态记载未知问题标注、满意度分析、消息看板、从会话提取问答，以及问答转人工和工作流等更新；开通条件和具体版本需分别确认。[产品动态](https://cloud.tencent.com.cn/document/product/1177/111858)

计费页分别列机器人年费和人工坐席。当前基础机器人刊例价为 20,000 元每年，人工专业坐席为 3,000 元每用户每年且至少三用户，不应把机器人单价当整套成本。[计费概述](https://cloud.tencent.com/document/product/1177/40561)

适配判断：借鉴会话标注、知识维护与人工后续的连接。其完整采购和配置体系对小商家的门槛可能较高，我们优先提供明确待办和下一步。

### 晓多语流 Agent

语流公开页宣称商品图文和参数初始化、主流电商平台及多店策略、从历史人工回复学习；有试用和效果付费描述，但公开页没有足以核算账单的完整规则，不能据此承诺零配置效果。[语流官方页](https://www.xiaoduoai.com/product/mindflow)

公开问答帮助有行业知识、逐条问答、批量导入、重复检测和条件不足时反问。客服工作台帮助分别处理“是否解决”和“满意度／不满意原因”。这些旧帮助与最新语流的版本对应关系未明确，不当作最新版菜单实测。[问答知识帮助](https://cvd.xiaoduoai.com/v1/unit/help_doc?id=118)、[工作台帮助](https://cvd.xiaoduoai.com/v1/unit/help_doc?id=114)

适配判断：电商先问规格、地区、渠道等必要条件，区分问题解决与满意度。不能将通用行业知识、过时人工回复或个案优惠自动变成本店正式承诺。

### FastGPT

官方 Agent V2 调试帮助描述自然语言辅助配置，以及在回答气泡中标注期望答案、进入知识维护的操作；辅助生成存在商业版限制。[生成和调试](https://doc.fastgpt.cn/zh-CN/guide/build/agentv2/debug)

官方 FAQ 明确修改后需重新发布才影响正式渠道；Beta 评测可组织问题和标准答案、逐条看结果，当前明确只包含回答准确性，不能扩张为全面质量保证。[发布 FAQ](https://doc.fastgpt.cn/zh-CN/guide/build/faq)、[评测 Beta](https://doc.fastgpt.cn/zh-CN/guide/build/evaluation)

当前云服务价格页列免费、99 元每月基础和 599 元每月高级等层级，按积分、容量、成员、日志保留分层，不是每次已解决咨询单价。[定价](https://fastgpt.cn/price)

适配判断：学习问题到期望答案、复测和显式发布；模型参数、节点和检索调参应藏在系统内部。它是邻接构建平台，不直接等同消费者人工接待运营系统。

## 第一轮统一决策

首轮交付“发现问题 → 确认修正 → 原题验证 → 发布追溯”，加可信人工联系出口和资料自检。新建两张增量表；不批量改写历史草稿、版本、消息，不建立收费资源，不自动从聊天学习并上线，不推定解决率。

消费者主动反馈自动进入待办、自动聚类、批量评测留待后续。初期由商家在真实咨询明确标记，让有限开发量优先形成可靠闭环；不能将这些后置能力写为已实现。

## Web 和 WorkBuddy 的任务分工

| 任务                                 | 优先入口          | 权限与边界                                            |
| ------------------------------------ | ----------------- | ----------------------------------------------------- |
| 行业访谈、整理资料、起草 FAQ、补缺项 | Web 和独立 Skill  | 用户提供资料；不把生成内容直接当事实                  |
| 查看原咨询、维护政策、修正、逐项验证 | Web               | 当前商家登录、成员关系、可见来源及版本                |
| 自然语言读取有权后台、创建纠正草稿   | 后续 MCP 加 Skill | 服务端认证、商家选择、最小权限；不相信模型自报商家 ID |
| 确认发布、停止服务和高影响变更       | Web 优先          | 展示准确修订、独立确认，不隐含在生成动作中            |
| 消费者咨询                           | H5                | 不要求消费者安装 WorkBuddy 或拥有商家账号             |

WorkBuddy 官方定义 Skill 为指令和资源包；已有网络服务可用 MCP 加 Skill，并要求 HTTPS 和鉴权，支持服务自身 OAuth 与 PKCE 等流程。安装包不等于后台账号授权。[Skill 文档](https://open.workbuddy.cn/docs/skill)、[Connector 文档](https://open.workbuddy.cn/docs/connector)

现有源码的 OAuth token codec、resource owner authorizer 和本地授权运行时仍有 Unavailable 实现；公网 MCP 不应直接开启。依赖为真实登录、商家选择和 consent、令牌签发校验/刷新/撤销、租户权限、幂等写入、客户端实测。只有需要 WorkBuddy 自身 Open API 身份时才另接其应用凭据。这不阻碍本轮 Web 改善。

## 验收口径和场景

功能可用、回复合理、商家能够持续改善分别验收，绝不以 HTTP 200、模型返回文字或 completed 状态代替“问题解决”。没有实测数据就不报准确率。

场景包括型号不明问价、新疆运费缺失、优惠期限/门槛不清、两处售后政策冲突、未知库存、投诉、人工需求。代表性闭环以零售保温杯为例：消费者问新疆包邮，商家从原会话标记缺口；补充“新疆需另核运费”，复测不能无条件承诺包邮，商家判定后发布，新会话取新规则，旧会话和旧快照保持不变。

必须有真实 MySQL 的租户、并发、幂等、迁移兼容和发布事务验证，以及少量现有千问模型的代表性问题实测。纯 mock 可证明状态机和错误处理，不能证明真实模型回答质量。

本文件是研究及本轮范围决策；实现、构建、数据库集成、真实模型和可体验入口分别在后续验收记录逐项记结果，不提前宣称已上线。
