# 商家持续改善客服使用指南

适用版本：R1 候选。当前尚未切换公网；发布状态以本轮验收记录为准。已有商家继续使用原来的专属后台，不需要重新创建商家或重新领取账号。

## 从哪里开始

登录自己的商家后台后，进入“咨询管理”。打开一条回答不好的真实咨询，在对应的消费者问题下面选择“改进这条回答”。也可以从“问题与改进”选择客服，手工建立一个需要验证的场景。

商家后台路径是 `/{商家ID}/…`，问题列表是 `/{商家ID}/improvements`。不要使用别的商家的地址，也不要把商家管理链接发给消费者。消费者使用“测试与发布”中生成的 `/a/…` 链接。

## 一 建立一个值得改的问题

选择符合实际的原因，填写“商家期望答案”。写清商品或服务、适用条件、价格和政策依据，不只写“回答得更好一点”。

例如消费者问偏远地区运费，期望答案应说明适用地区、商品数量、费用及包邮条件；如果尚未核实，就先写需要补充的事实，不让 AI 猜金额。示例价格不是你店铺的真实报价。

从真实咨询建立任务时，原问题、原回答和当时的正式版本会保留，不能修改原记录。商家备注只供自己跟进，不单独发送给模型。

## 二 核对并写入草稿

先保存期望答案，再查看完整的 FAQ 修正预览。确认事实真实、有效后，勾选确认并选择“应用修正到草稿 FAQ”。

这个动作只修改未发布草稿，不改变消费者当前看到的版本。原来的资料确认会失效，之后需要重新核对。商品或服务资料合并后最多 4000 字，超过时会拒绝，不会截断原资料。

如果同一任务需要再次修正，系统替换它自己原来的 FAQ 块；不会一直叠加旧的错误答案。如果你手工改过该块，系统会要求你核对，避免覆盖人工修改。

如果价格、优惠或其他原字段仍有冲突，也要去相应字段修正。增加一段 FAQ 不会自动删除其他地方的矛盾政策。

## 三 用原问题复测

核对发送范围，同意将当前草稿与本条问题发送至阿里云千问，再选择“发送问题并记录复测”。测试可能产生模型调用费用；备注不单独发送，消费者正式版本不会因为测试而改变。

实际回答会保存在任务中。发送后暂时没有结果，不要换一个请求反复点击；先刷新核对同一条任务。浏览器不能可靠保存请求记录时，会阻止提交，避免意外重复创建或调用。

## 四 阅读实际答案并判定

核对回答有没有根据商家资料说明条件，有没有猜价格、编库存、承诺退款或假装转人工，再选择通过或不通过。

“调用完成”只表示收到文字；“商家判定通过”只表示这条问题在对应草稿下经过你的核对，不代表所有消费者问题都已经解决，也不会自动发布。

改动期望答案、草稿或相关策略后，原测试会过期。旧版本的通过不能覆盖当前失败、待审阅或未测试状态。需要重新测试当前修订。

## 五 确认资料并发布

在任务底部进入“核对并确认知识资料”，检查当前修订并确认；然后进入“测试与发布”，阅读发布条件，勾选独立发布确认，再发布。

发布成功且本任务的有效测试与正式修订一致时，任务才显示关联当前线上版本。如果后来修改了版本，历史发布记录仍保留，但不保证新内容已经验证。

发布不会更换固定消费者链接。验证新内容时请新建消费者咨询；已有咨询保持建立时的旧版本，刷新旧咨询不等于切到新规则。

## 六 人工与投诉怎样处理

在客服草稿中填写真实的“人工联系说明”，例如实际联系方式、服务时间和需要消费者提供的订单信息，确认后发布。消费者 H5 只展示已经发布的说明。

本轮没有实时坐席接入、自动通知、工单受理或代办退款。修改一条投诉回复不代表投诉已经解决，也不代表商家已收到通知。商家仍应通过真实渠道处理，并在原咨询中单独更新人工跟进状态。

## 常见问题

| 遇到的情况                     | 下一步                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------ |
| 保存后不知道有没有生效         | 看页面显示的新修订与保存提示，重新打开核对已保存内容；未发布时消费者仍用旧版本 |
| 已确认后又修改资料             | 新修订必须重新核对，确认勾选不会沿用旧修订；不需要反复新建客服                 |
| 提示版本变化或冲突             | 保留当前文字，重新读取并对照新修订，不强行覆盖其他页面的修改                   |
| 提示结果尚未确认               | 先查看当前任务；保留原请求上下文，不更换请求重复提交                           |
| 模型失败或超时                 | 查看保留的失败记录；核对服务后明确重试，失败不算通过                           |
| FAQ 超过字数或人工块被改动     | 手工整理并核对原资料，再应用；系统不会静默截断或覆盖                           |
| 已发布，旧消费者仍按旧规则回答 | 使用“新建咨询”验证新版本，旧咨询保留原快照                                     |
| 找不到商家或提示无权限         | 使用本商家的完整管理链接重新登录；不能通过修改商家 ID 获得权限                 |

后台“帮助中心”与下载手册也包含这些步骤。资料自检只是常见缺项提醒，不是质量分数；行业模板也不能替代本店真实商品和政策。
