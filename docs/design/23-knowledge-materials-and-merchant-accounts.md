# 文件材料知识库与商家账号管理

## 范围与使用流程

商家在自己客服的知识库上传基础材料，检查提取文字，选择材料生成整理稿。整理稿经人工核对后保存到客服草稿，再确认资料、试聊和发布。上传或生成整理稿不会自动修改已发布版本。运营在商家详情查看真实可登录的固定账号，核对其全部关联商家后重置密码。

本次不增加云资源、存储服务或数据库迁移，不恢复 WorkBuddy。沿用 MySQL、既有知识来源和修订表以及现有发布快照。发布前还需完成代码审查、候选镜像验证及私有环境验收；本设计本身不代表已上线。

## 文件解析与材料存储

支持 PDF、DOC/DOCX、PPT/PPTX、XLS/XLSX、TXT、CSV、Markdown，使用固定版本 `@kreuzberg/node` 的原生解析器。上传在同源、CSRF 和商家／客服成员校验后进行，文件不交给系统 Office 软件执行。解析在受控子进程运行，不传入数据库、模型或身份凭据，不将用户文件名作为命令；超时终止所属进程。文件签名、压缩容器和解析配置共同限制资源使用，不只依赖扩展名。

单份最多 10 MiB，每批最多 5 份、合计 20 MiB，单份提取文字最多 24000 字。每个客服最多 50 份材料；不默默截断文字。解析器每个应用进程最多两个并发任务，商家容器设 1024 MiB 内存及 128 个进程上限。网关请求限额保留 multipart 头部开销。扫描件 OCR、加密文件、宏文档执行、远程链接抓取和实时库存同步不在范围内。

MySQL 的 `knowledge_source` 使用 `uploaded_file` 类型，`knowledge_revision` 保存 `pending_review` 的提取文字、文件大小、原文件 SHA-256 和解析版本。原二进制不长期保存，界面提示商家保留原件。不同商家与不同客服的来源查询均带作用域，不开放公共材料下载。全部失败返回失败，部分成功分别列出已保存项目与具体错误。

## 整理与发布边界

只有商家明确同意后，所选材料文字才通过内部认证接口发送到阿里云千问。每次选择 1–5 份、合计最多 24000 字；模型凭据仍只在 Worker。输出必须是受约束 JSON：最多 4000 字的整理稿及最多 10 条提醒。系统提示保留来源、数值和适用条件，冲突与缺失事项要求商家确认；数值护栏用于发现新增数字，不作为答案准确性证明。

商家可编辑整理稿，默认追加至现有“商品或服务资料”，也可明确选择替换。合并后仍限 4000 字，不自动覆盖价格或优惠字段。保存时使用草稿修订比较并加锁，旧修订不能覆盖新编辑；保存使原知识确认失效。后续沿用原确认与发布逻辑，消费者会话只读取已发布快照，而不是待审材料库。完整文件全文不会自动进入检索或模型上下文。

## 账号与密码

历史手机号只有不可逆查询摘要，不尝试恢复。固定账号为 `m_` 加商家用户 ID，是新增的合法登录标识；原手机号登录保持兼容。只有已登录的运营人员可在商家详情读取账号与角色，不展示手机号、旧密码、盐或密码摘要。一个账号可以关联多个商家，重置界面列出完整名称和编号。

重置要求有效运营会话、同源请求、当前运营密码、新密码两次一致、固定原因和影响确认。密码长度沿用 12–128 字符，服务端随机盐加 scrypt 保存。提交同时核对账号版本和全部活跃成员关联；范围变化、重复关联编号或旧版本都拒绝。审计只记录固定原因、操作人、目标账号及受影响商家，不接受自由备注或密码。

登录和重置都锁定同一凭据记录，避免旧密码登录在重置完成后补发会话。更新密码、撤销该账号全部平台登录会话和写审计在同一事务内完成。其他账号、商家启用状态、消费者会话和已发布客服不受影响。WorkBuddy 连接与 OAuth 令牌管理不由本次 Web 功能扩展。

## 验证与交付

PDFium 在构建阶段预热到固定的只读 `parser-runtime` 目录，最终镜像保留原生库，解析子进程只使用该固定目录。镜像冒烟测试会在非 root、只读根目录及 `/tmp:noexec` 下实际解析合成 PDF 和文本，不通过放宽临时目录权限解决依赖加载问题。

商家镜像使用固定摘要的 Node 24 Trixie slim，以满足解析器需要的 C++ ABI；其余四个应用保持原 Bookworm 基线，不混装跨发行版系统库。镜像摘要来自 [Docker 官方镜像清单](https://raw.githubusercontent.com/docker-library/repo-info/master/repos/node/remote/24-trixie-slim.md)，构建和运行阶段使用相同应用基线。

单元测试覆盖格式、限额、作用域、来源和 CSRF、模型同意、数字护栏、修订并发、受控审计原因和密码不回显。隔离 MySQL 集成测试验证共享账号、全会话撤销、非目标账号保留以及登录与重置两种行锁竞态。浏览器测试运行根路径、管理子路径和单域名三种模式，验证上传到消费者回答使用新知识，以及旧密码拒绝、新账号与新密码登录。

部署必须同时更新商家端与 Worker，核对原生解析依赖及脚本进入最终镜像、Nginx 请求大小和容器限额。保持公网仅有既有 Web 入口，不新增数据库或解析端口。无需数据迁移；回退代码不会删除已保存材料或恢复旧密码。重置是已生效的业务写入，不能通过回退镜像撤销。
