# H5 AI客服生成与管理平台：产品域与UX设计

> - 文档版本：V0.1（评审稿）
> - 依据：`H5_AI客服生成与管理平台_产品需求分析_V1.0.md`
> - 本文用途：明确产品边界、角色权限、三端信息架构、关键流程、页面状态与验收映射。本文只做设计，不代表研发排期或功能承诺。

## 1. 需求状态与阅读规则

### 1.1 状态标签

本文对每项设计使用以下标签，标签优先于“P0/P1/P2”优先级：

| 标签 | 含义 | 处理方式 |
| --- | --- | --- |
| **[M] 已明确** | 原需求中已明确的产品目标或约束 | 作为设计必须满足的边界 |
| **[R] 建议基线** | 原需求建议的首版方案，或为形成闭环提出的默认设计 | 进入原型或开发前仍需评审确认 |
| **[Q] 待确认** | 会影响范围、成本、合规或用户行为的未决项 | 不可作为已承诺功能；需形成决策记录 |
| **[O] 范围外** | 已明确不纳入当前首版，或归入后续阶段 | 当前仅保留扩展边界，不展开实现 |

优先级只表达“若方案获批时的实施先后”，不改变需求状态。例如“P0 [R]”表示“建议首版纳入，但尚未承诺”。

### 1.2 产品原则

1. **[M] 商家级知识共享、消费者会话隔离。** 同一商家客服可使用其已发布知识，不同消费者的消息、摘要、需求状态和联系方式不可混用。
2. **[M] 商家事实必须有依据。** 价格、库存、服务承诺、订单、预约与退款结果不可由模型补造。
3. **[M] AI身份透明。** H5明确展示AI客服身份，不伪装真人，不编造真人经历。
4. **[M] 消费者无需WorkBuddy账号。** 在线H5由平台持续提供，WorkBuddy关闭后不影响消费者咨询。
5. **[R] 草稿与线上版本分离。** 编辑不直接影响线上；发布后固定H5入口不变。
6. **[R] 低门槛咨询。** 消费者可匿名先提问，只有在需要跟进时才按用途最少收集联系方式。
7. **[R] 可解释失败。** 暂停、额度不足、知识处理失败、模型异常、提交失败等状态都给出原因和下一步，不伪装成功。
8. **[M] Skill不收集登录密码。** WorkBuddy中的身份识别必须来自受控授权上下文；登录、验证码、通行密钥或第三方授权只能在平台的安全页面完成，Skill不得在对话中索取、回显、转发或保存明文密码。

## 2. 产品域与范围分层

### 2.1 产品域边界

本产品由三个面向用户的体验面和一个辅助入口组成：

- **商家管理端**：创建、配置、测试、发布AI客服，维护知识，查看咨询与用量。
- **消费者H5**：通过商家公开链接发起连续咨询，必要时提交需求或联系商家。
- **平台运营端**：管理商家、客服状态、模板、用量、异常和审计。
- **WorkBuddy Skill辅助入口**：按官方远程业务服务建议采用MCP+Skill连接平台能力，帮助商家完成首次生成、后台跳转及后续修改、测试和发布；不承载消费者在线会话。MCP是受控适配面，不取代平台的业务鉴权与事实存储。

产品域不等同于为每个商家独立部署一套站点。[R] 建议使用统一H5程序，通过不可枚举的公开客服标识加载不同商家已发布配置；公开标识只定位客服，不具备会话读取或管理权限。

### 2.2 P0/P1/P2边界

#### P0：建议首版最小闭环（均为 [R]，待评审确认）

| 能力域 | P0建议包含 | 明确边界/不包含 |
| --- | --- | --- |
| 商家账号与商家档案 | 商家登录；维护商家名称与基础联系资料；一个商家一个客服入口 | 登录方式、找回方式与运营开通流程 [Q]；数据模型可预留多客服但界面不开放 |
| 客服创建与配置 | 行业、细分领域、工作方向、业务介绍；回答范围；问答/需求收集模式；风格；欢迎语；快捷问题；联系入口；营业时间与AI状态 | 生成的真实业务事实必须由商家确认；必填字段清单 [Q] |
| 知识维护 | 手工FAQ、文本录入、可提取文字PDF；处理状态；来源/更新时间/适用范围；修改后形成草稿 | PDF是否最终进入首版 [Q]；不承诺扫描件OCR、网页抓取、表格与音视频解析 |
| 测试与发布 | 草稿、手机预览、试聊、发布、固定H5链接/二维码、线上版本、暂停、回滚 | 版本差异颗粒度与“强制结束旧会话” [Q]；不做复杂审批流 |
| 消费者H5 | 匿名访问、AI标识、快捷问题、流式文字对话、会话内上下文、刷新恢复、新建咨询、失败重试、需求提交/联系商家 | 会话时长、历史展示和保留 [Q]；不做跨Session个人长期记忆 |
| 咨询管理 | 会话列表/详情、摘要、需求字段、未解决原因、人工跟进状态、反馈查看、知识补充草稿 | 不提供真人在线坐席与全渠道收件箱；自动判定与人工标记的边界需在原型中说明 |
| 用量与运营 | 商家用量概览、额度/限流状态；运营查看商家/客服状态、模板、用量、失败告警、审计 | 具体配额、并发、限流数值与计费规则 [Q]；P0可由运营人工开通额度 |
| WorkBuddy Skill | 双入口：首次创建时分步收集行业、业务资料与售卖策略，确认后生成草稿并返回管理链接；已有客服时识别已授权用户并返回其后台地址；后续再扩展修改、测试和发布 | 目标WorkBuddy版本、安装、网络和凭据能力未验证 [Q]；生成不等于发布；不在对话中收集密码；不承诺已可安装交付 |

P0成立的最小业务闭环是：**商家能用真实资料创建并发布客服 → 消费者能匿名连续咨询且不会串话 → 商家能查看咨询并修正知识 → 新版本可验证后发布，原链接继续可用。**

#### P1：扩展经营能力（[O]，后续候选）

- 更多文档类型与批量知识导入。
- 一个商家多个客服、多门店、多入口与适用范围管理。
- 商家团队、成员邀请、细粒度角色与发布审批。
- 自助订阅、套餐变更、用量购买及账单。
- 更完整的知识质量运营、批量测试与效果分析。

P0只在数据和导航结构上避免阻断这些扩展，不提前实现P1交互复杂度。

#### P2：业务系统连接（[O]）

- 真人坐席与实时转接。
- 订单查询、库存查询、预约占位与确认。
- 支付、退款与交易状态处理。
- 跨渠道消息接入及统一会话中心。

在P2接口真实接通前，H5只能提供已配置联系渠道或登记需求，不能展示“已转接”“已预约”“已核实订单”“退款成功”等执行结果。

#### 首版明确不包含（[M]/[O]）

- 语音对话、数字人。
- 跨Session个人长期记忆。
- 消费者发言自动写入正式知识。
- 全渠道消息接入。
- 仅依据模型推断真实库存、预约名额、订单或退款状态。

## 3. 角色、权限与数据可见性

### 3.1 角色模型

| 角色 | 核心目标 | 可执行操作 | 不可执行操作/约束 |
| --- | --- | --- | --- |
| 平台超级管理员 [R] | 管理平台级策略与运营账号 | 管理商家状态、运营角色、模板、额度、全局异常；按授权发起审计查看 | 不以公开H5身份访问管理数据；敏感操作必须留痕 |
| 平台运营 [M] | 服务商家、处理异常、管理模板与用量 | 在岗位授权内查看商家/客服状态、用量、任务失败；执行开通/暂停等被授权操作 | 访问消费者会话需有业务依据并留痕；不可获得模型密钥 |
| 商家管理员 [M] | 创建并经营本商家AI客服 | 管理本商家档案、客服配置、知识、发布版本、咨询、需求和用量 | 不可查看其他商家数据；不可把聊天指令当管理操作 |
| 商家成员 [O/P1] | 分工维护或跟进 | 按未来授权管理知识、咨询或发布 | P0不开放团队协作；当前不假设该角色可用 |
| 匿名消费者 [M] | 获取咨询并连续追问 | 访问公开H5；读写自己有效凭据绑定的Session；提交需求/反馈 | 无后台权限；公开客服标识或session_id均不能单独授权读取会话 |
| WorkBuddy Skill调用方 [M/R] | 代商家完成受限管理操作 | 经商家身份与权限验证后进入“首次生成”或“已有客服”流程；保存可恢复采集进度；经用户确认创建草稿；返回受保护的管理链接 | 不管理消费者Session；不索取密码；不把管理链接当授权凭据；不绕过商家权限；凭据不进入聊天或公开Skill包 |

“平台超级管理员”与“商家成员”是为权限设计完整性提出的角色拆分，[R]/[O] 不代表首版必须提供独立界面。

### 3.2 权限矩阵

图例：`管理`=可创建/修改/执行；`查看`=按范围只读；`受控查看`=需岗位权限、业务理由和审计；`本人`=仅凭有效访客凭据访问本会话；`—`=无权限。

| 资源/动作 | 平台超级管理员 [R] | 平台运营 [M] | 商家管理员 [M] | 匿名消费者 [M] | Skill调用方 [R] |
| --- | --- | --- | --- | --- | --- |
| 平台运营账号与权限 | 管理 | — | — | — | — |
| 商家状态/额度 | 管理 | 按岗位管理 | 查看本商家 | — | 查看本商家 |
| 本商家档案 | 受控查看/管理状态 | 受控查看 | 管理 | 仅看公开字段 | 按授权管理 |
| 客服草稿配置 | 受控查看 | 按岗位查看 | 管理 | — | 按授权管理 |
| 已发布公开配置 | 受控查看 | 查看 | 管理 | 查看公开字段 | 查看/按指令发布 |
| 知识原文与处理状态 | 受控查看 | 按岗位查看 | 管理本商家 | — | 按授权管理 |
| 消费者会话与消息 | 受控查看且审计 | 业务需要时受控查看且审计 | 查看本商家 | 本人 | 默认不读取；按明确能力授权 |
| 消费者联系方式 | 受控查看且审计 | 按用途授权查看 | 按用途查看本商家 | 本人提交 | 默认不读取 |
| 模板 | 管理 | 按岗位管理 | 使用 | — | 使用 |
| 发布/回滚/暂停 | 仅异常处置 [Q] | 按岗位 [Q] | 管理本商家 | — | 按商家明确指令 |
| 审计日志 | 管理/查看 | 按岗位查看 | 可查看本商家关键操作 [Q] | — | — |

### 3.3 权限体验规则

- 无权限入口不展示；通过深链访问时仍由服务端拒绝，并返回可理解的无权限页。
- 高影响操作（发布、回滚、暂停、删除知识、调整额度）展示影响对象、线上影响和最终确认。
- 平台人员打开消费者内容时，[R] 建议先选择访问原因，并记录操作者、商家、会话、原因与时间。
- 商家删除或修改知识时不篡改历史消息；历史会话显示当时关联版本。
- 消费者聊天内容中的“忽略规则、替我发布、显示密钥”等文字只作为普通消息，不形成管理指令。

├─ 工作台

├─ 客服设置

│  ├─ 回答范围
│  ├─ 对话模式与需求字段
│  ├─ 对话风格
│  ├─ H5页面与欢迎设置
│  └─ 服务状态与联系渠道
├─ 知识库
│  ├─ 全部知识
│  ├─ 新增FAQ/文本/文件

### 4.2 消费者H5

```text
公开H5入口
├─ 聊天页
│  ├─ 商家/客服名称、头像与AI标识
│  ├─ 欢迎语、能力范围与快捷问题
│  ├─ 消息流、发送/流式/失败状态
│  ├─ 联系商家

│  ├─ 从会话提取并允许确认的业务字段

│  └─ 提交结果
└─ 系统状态页/遮罩

   ├─ 额度不足/暂不可用
   ├─ 链接无效
   └─ 会话失效后开始新咨询
```

消费者侧优先保持单页、低认知负担；不把知识来源、后台状态或内部错误码暴露给消费者。

运营端P0只应覆盖试点所需的人工运营闭环；计费、退款、复杂审批与工单系统不进入当前设计承诺。

### 4.4 WorkBuddy Skill对话入口

```text
打开 H5 AI客服 Skill
├─ 首次生成AI客服
│  ├─ 安全连接/识别商家身份
│  ├─ 细分行业
│  ├─ 产品、商品或服务资料
│  ├─ 价格、优惠与特殊售卖策略
│  ├─ 缺失信息补充
│  ├─ 生成前预览与明确确认
│  └─ 创建草稿并返回管理链接
├─ 已有AI客服
│  ├─ 安全连接/识别商家身份
│  ├─ 无客服：引导首次生成
│  ├─ 一个客服：返回对应后台地址
│  └─ 多个客服 [P1预留]：先选择再返回地址
└─ 通用命令
   ├─ 帮助 / 为什么要问
   ├─ 查看进度 / 还缺什么
   ├─ 修改上一项 / 修改某一项
   ├─ 暂停并稍后继续
   └─ 取消
```

入口可由明确按钮、快捷选项或自然语言意图触发。意图不明确时只问一次选择题：“你想首次生成AI客服，还是打开已有AI客服后台？”Skill不得因为用户说了“帮我看看客服”就猜测并创建资源。

“管理链接”只是登录后页面的深链，不是Bearer Token或会话凭据。链接不得携带密码、Access Token、Refresh Token、验证码、访客凭据或可复用授权码；未登录或权限已撤销时，浏览器仍须在平台侧完成认证和服务端鉴权。

## 5. 关键用户流程

### 5.1 商家首次创建与发布

1. 商家登录，若无商家档案则进入创建向导。
2. 输入商家名称、客服名称、行业/细分领域/工作方向与业务介绍。
3. 系统生成**结构化配置草稿**，所有生成项可编辑；真实价格、库存、营业承诺等缺失信息标记为“待补充”，不得补造。
4. 商家提供FAQ、文本或建议支持的文件；系统逐项展示处理状态。
5. 商家设置回答范围、对话风格、问答/需求收集模式、欢迎语、快捷问题和联系渠道。
6. 商家进入试聊，覆盖正常问题、资料不足、越界问题和需求收集。
7. 发布检查显示：阻断项、风险提示、与线上版本差异；无线上版本时显示“首次发布”。
8. 商家确认发布；只有服务端返回真实成功后，界面才进入“已发布”并提供固定链接与二维码。
9. 若发布失败，保留草稿和既有线上版本，展示失败原因与重试入口。

发布门槛中“商家名称、客服名称、业务范围、欢迎语、无法回答策略、至少一条可用业务知识”为 [R] 建议基线，字段清单需评审确认。

### 5.2 商家维护知识并发布新版本

1. 商家新增、修改或删除知识，变更进入草稿，不影响线上。
2. 文件或文本完成处理后进入“可用于草稿”；失败项显示原因，可替换或重试。
3. 冲突、过期、缺少适用条件的内容进入待确认清单 [R]。
4. 商家在试聊中验证变更，并查看草稿与线上差异。
5. 发布生成新版本，固定H5链接不变；新Session使用新版本。
6. [R] 进行中的Session继续使用建立时版本。若必须立即失效，商家可先紧急暂停；是否开放“结束旧会话并提示重开”属于 [Q]。
7. 回滚将当前发布指针重新指向仍完整可用的历史Release，不复制或修改历史Release；UX必须保留新的激活审计记录并明确影响范围。

### 5.3 消费者首次咨询、刷新恢复与新建咨询

1. 消费者打开商家链接，页面先校验客服是否存在、已发布且可服务。
2. 页面展示商家/客服身份、AI标识、欢迎语和快捷问题，不强制提交手机号。
3. 系统创建匿名访客凭据与Session，或恢复该访客在当前客服入口下的有效Session。
4. 消费者发送问题；发送中锁定该条消息的重复提交，回复以流式状态展示。
5. 消费者连续追问时复用本Session已确认的上下文，不重复询问已有信息。
6. 刷新或短暂离开后，凭有效访客凭据恢复消息与未过期Session。
7. 主动“新建咨询”前提示“当前上下文将结束”；确认后创建新Session，不继承旧需求状态。
8. [R] 超过有效期后，下一次发送时创建新Session并提示“已开始新的咨询”；30分钟仅为 [Q] 中的建议值。

### 5.4 资料不足、越界与故障分流

| 判断结果 | 消费者回复策略 | 商家侧记录 |
| --- | --- | --- |
| 资料充分 | 直接回答，必要时说明条件 | 记录回答所用版本与可追溯来源 |
| 缺少必要条件 | 只追问影响答案的最少条件 | 更新本Session需求状态 |
| 缺少业务依据 | 明确“暂无法确认”，提供联系/需求登记 | 标记未解决：资料不足 |
| 知识冲突 | 不给确定承诺，提示需商家确认 | 标记未解决：知识冲突 |
| 超出服务范围 | 简短说明范围，并引导回可服务事项 | 可记录越界类型，不进入正式知识 |
| 模型/检索故障 | 展示服务异常与重试，不生成业务结论 | 标记技术故障与请求标识 |
| 额度不足/客服暂停 | 停止新增模型调用，解释当前不可用，展示已配置联系入口 | 记录限流/暂停原因 |

### 5.5 需求收集与联系商家

1. 在需求收集模式中，系统从当前Session提取已提供的服务类型、地区、规格、时间等字段，并标明来源。
2. 仅逐步追问业务必要字段；已有信息不重复问，消费者纠正后以新值为当前值但保留消息来源。
3. 消费者主动选择“请商家联系我”或达到可提交条件时，打开需求确认界面。
4. 页面展示本次提交内容；联系方式按配置设为选填或业务必要字段 [Q]，并说明用途。
5. 提交按钮需防重复；成功只表达“需求已登记”，不表达“商家已接受/预约成功”。
6. 若商家仅配置电话或企业微信，则提供真实渠道，不显示“已转接人工”。

### 5.6 商家处理咨询并改进知识

1. 商家从工作台进入待处理/未解决咨询。
2. 会话详情展示原始消息、摘要、需求字段、关联客服版本和未解决原因；摘要不替代原始记录。
3. 商家将跟进状态从“待处理”改为“处理中/已处理” [R]，该状态明确为人工运营标记。
4. 对资料不足问题，商家可“生成知识补充草稿”；草稿必须由商家确认后才能进入待发布版本。
5. 发布新知识不修改历史回复，也不自动把消费者原话变为正式知识。

### 5.7 暂停、恢复与回滚

1. 商家选择暂停时，确认弹层说明“对所有新消息立即生效”；是否保留历史只读访问由会话展示策略决定 [Q]。
2. 暂停成功后，商家端显示暂停原因、操作者与时间；H5显示可理解提示和已配置联系渠道。
3. 恢复服务前执行发布状态和额度检查；恢复不等于发布草稿。
4. 回滚前展示目标版本、当前版本、差异和对新/进行中Session的影响；回滚成功后保留审计记录。

### 5.8 WorkBuddy Skill双入口流程

#### 入口一：首次生成AI客服

1. **识别意图。** Skill确认用户希望创建新客服，而不是打开已有后台或咨询消费者问题。
2. **建立安全身份上下文。** 若尚未连接平台，Skill返回平台官方HTTPS绑定入口，在浏览器内完成平台登录，并由项目第三方应用发起OAuth；对话中明确提示“请勿发送密码或验证码”。经官方核验，OAuth `/token`服务端换票响应包含`open_id`。平台用服务端密钥对长度明确编码的`(issuer, client_id, open_id)`整体做HMAC，保存其结果作为外部身份查找键，不保存或按明文查询`open_id`，也不把昵称、手机号或商家名称当唯一身份。普通Skill/Connector不被假设能自动取得`open_id`；换票、绑定与MCP会话衔接必须在目标版本实机验证通过。绑定成功后，Skill只读取平台映射出的用户、商家、角色与scopes。若用户拥有多个商家，只能从已授权列表中选择，不能让模型根据名称猜测租户。
3. **识别细分行业。** 首问采用开放描述：“请用一句话说明你主要卖什么或提供什么服务，以及主要服务谁。”系统提出一个规范化的细分行业候选并请用户确认；过于宽泛时只追问一个最能区分业务的问题，例如服务对象、交付方式或主要场景。
4. **收集产品/商品/服务资料。** 至少收集一项业务对象的名称、核心说明和适用对象。按行业按需追问规格/套餐、服务区域、交付方式、营业时间、限制条件和常见问题；用户可回答“暂无/不确定”，系统将其标记为缺失，不能自行补齐。
5. **收集价格与特殊售卖策略。** 明确询问是否存在价格、单位、起步条件、套餐、满减、折扣、赠品、阶梯价、会员价、渠道价、区域价、有效期或其他特殊策略。用户回答“没有”时记录为“用户确认暂无”，不能与“尚未提供”混为一谈；任何优惠必须同时保存适用条件和有效期（若未知则标缺失）。
6. **最少追问缺失项。** Skill每轮最多聚焦一个主题；先说明为什么需要，再给出可直接照抄的回答示例和“暂时跳过”选项。发布所需但尚缺的信息进入`missing_fields`，可选项不反复打扰。
7. **生成前预览。** 展示商家、细分行业、业务条目数量、价格/优惠摘要、明确缺失项和将执行的动作：“仅创建可编辑草稿，不发布、不产生消费者可访问链接”。涉及真实事实的内容标记为“由你提供”；整理或改写内容标记为“系统建议”。
8. **确认或修改。** 只接受本轮用户对该预览的明确“确认生成”；“好的”“继续看看”等含糊表达应再次确认。用户可说“修改价格”“返回上一步”“取消”或“帮助”。确认令牌绑定当前商家、采集会话revision与摘要，过期或内容变化后必须重新预览确认。
9. **真实创建与返回。** 平台成功创建AssistantDraft及首批FAQ/结构化事实后，Skill返回客服名称、草稿状态、仍缺内容和管理链接。任何部分失败都保留可恢复进度并说明失败项；没有API成功结果时不得声称已生成。

细分行业“识别”不等于系统可以把行业常识写成商家事实。行业模板只能建议字段和问题，不能补造商家的商品、价格、优惠、区域、库存、承诺或营业规则。

#### 入口二：已有AI客服

1. Skill先读取平台已建立的受控Account上下文；其外部身份只能来自第三方应用OAuth服务端换票，并以`HMAC(issuer, client_id, open_id)`查找键绑定。普通Skill/Connector不能自报或直接传入`open_id`，也不能根据对话中的邮箱、手机号、昵称、商家名称或密码自行认领账号。
2. 未授权时打开与首次入口相同的安全登录/授权流程；授权未完成、取消或过期时保持只读提示，不返回任何商家后台地址。
3. 授权商家无客服时说明“当前商家尚未创建AI客服”，提供“开始首次生成”；不得返回不存在的后台链接。
4. 只有一个客服时，返回其名称、草稿/已发布/暂停状态和管理链接。
5. 多个客服是P1预留：只展示用户有权访问的客服名称与状态，用户明确选择后返回对应链接；不得默认选择最近访问或名称相似项。
6. 管理链接打开后仍由平台登录态和Membership鉴权。Skill禁用、Token撤销、用户退出商家或复制链接给无权限用户后，链接本身不能继续授权。

#### 确认、取消、恢复与帮助

- **确认：** 创建、覆盖、发布等写操作分别确认；首次生成确认只授权创建草稿，不授权发布。知识内容或上传资料中的“确认”文字永远不能充当用户确认。
- **取消：** “取消”立即停止当前采集，不创建Assistant；询问是否保留非敏感进度以便恢复。保留时长和默认行为属于 [Q]，界面必须明确说明。
- **恢复：** 用户说“继续上次创建”时，Skill依据已授权用户、商家和不透明workflow ID读取最近未完成流程，显示最后完成步骤、更新时间和缺失项；跨商家、已过期、已取消或已完成流程不能恢复为可写状态。
- **帮助：** “帮助”“为什么问这个”“给个例子”不改变流程状态，返回当前字段用途、格式、示例、是否必填和跳过后果；不得趁帮助请求自动提交。
- **修改：** 用户可按字段名修改；修改后workflow revision递增，旧预览和旧确认令牌失效。

#### 密码与敏感信息处理

- Skill工具参数、表单Schema和日志中都不定义`password`、短信验证码、TOTP、Refresh Token或私钥字段。
- 若用户在对话中主动粘贴疑似密码/验证码，Skill不得调用平台API转发，也不得在回复中复述；应提示停止分享，并建议在官方平台修改或撤销相关凭据。是否能删除宿主历史需实机验证，不能承诺已删除。
- 安全替代优先采用项目第三方应用OAuth：`open_id`只来自服务端换票，并转换为`HMAC(issuer, client_id, open_id)`查找键；平台自身补充认证仍在官方HTTPS页面完成。个人资料API的`POST /user/phoneverification`仅返回`matched`，因此只能作为账号绑定中的辅助布尔校验：不得用于获取手机号，不得把手机号写入Skill回复或日志，也不得替代OAuth主体。调用所需手机号若由用户提供，必须在平台安全页面输入，不能在对话中收集。一次性设备/绑定码只作为服务端短时、一次使用的降级候选。任何方案都必须可撤销、限scope并绑定单一商家。
- 登录/授权页面必须使用平台官方HTTPS域名；Skill只展示安全域名和用途，不让用户复制Token回聊天完成连接。
- 远程业务服务的连接形态采用官方推荐的MCP+Skill：Skill负责对话编排与确认，MCP Server只暴露白名单工具并使用已经完成绑定的平台Account上下文。第三方应用OAuth服务端换票是独立的身份绑定步骤，不能假设普通Skill/Connector自动获得`open_id`；原始OAuth Token、`open_id`、身份HMAC原料与手机号校验输入均不得作为模型可见内容。

#### Skill错误状态

| 状态 | 用户提示与动作 |
| --- | --- |
| MCP身份衔接尚未实机验证 | 明确说明当前不能安全识别账号，停止创建/跳转；不得用用户自报`open_id`、手机号或万能身份绕过 |
| 未连接/授权过期 | 说明需要在浏览器安全连接，提供重新连接；不索取密码 |
| 多商家待选择 | 展示已授权商家列表，请用户选择；不猜测 |
| Scope不足/成员关系失效 | 说明无创建或读取权限，提供切换账号/联系管理员；不泄露资源 |
| 行业描述过宽 | 追问一个区分问题，并提供2—3个示例答案 |
| 关键业务资料缺失 | 展示缺失项、影响和“补充/暂时跳过/取消” |
| workflow过期或已取消 | 说明不能继续写入；可查看安全摘要或重新开始 |
| revision冲突 | 停止提交，重新读取进度并展示变更；不得覆盖另一端修改 |
| 确认令牌过期 | 重新展示最新摘要并再次确认，不复用旧确认 |
| 创建部分失败 | 返回真实已保存内容、失败项、trace ID与安全重试入口；不返回虚假成功链接 |
| 平台超时/响应未知 | 使用原幂等键查询结果；确认前不得重复创建，不能自行断言成功 |

## 6. 页面规格与关键状态

### 6.1 通用状态规范

每个数据型页面至少设计以下状态：

- **首次空状态**：解释该页面用途，并提供单一主要行动。
- **加载状态**：保持页面骨架稳定，避免重复触发写操作。
- **正常状态**：展示更新时间、范围和主要行动。
- **筛选无结果**：保留筛选条件，提供清除筛选。
- **可恢复失败**：展示原因、重试入口与未丢失的数据。
- **无权限**：说明当前账号无权访问，不泄露资源是否存在。
- **部分成功**：逐项展示成功/失败，不把批量操作整体伪装为成功。

写操作统一具备“进行中—成功—失败”反馈；发布、需求提交、消息发送等操作使用唯一请求标识防止重复执行。

### 6.2 商家端页面与状态

| 页面 | 核心任务 | 关键内容/行动 | 必须覆盖的状态 |
| --- | --- | --- | --- |
| 工作台 | 判断下一步做什么 | 客服状态、完成度、发布入口、H5链接/二维码、待处理咨询、用量 | 未创建；草稿不完整；知识处理中；可测试；可发布；已发布；有未发布变更；已暂停；额度不足；系统异常 |
| 创建向导/客服设置 | 形成可编辑配置 | 分步字段、生成草稿、示例预览、保存状态 | 初始空白；生成中；生成失败；自动保存中/成功/失败；字段缺失；内容待确认；与线上有差异 |
| 知识库列表 | 判断知识是否可用 | 类型、标题、来源、适用范围、更新时间、有效期、处理状态、操作 | 空；待处理；处理中；可用；失败；冲突 [R]；过期 [R]；草稿删除；批量部分失败 |
| 知识编辑/导入 | 安全补充事实 | FAQ/文本表单、文件选择、来源、条件、单位、有效期 | 文件不支持；超限；上传中；解析中；解析失败；内容预览；待商家确认；保存冲突 |
| 测试与发布 | 验证后上线 | 试聊、测试问题、引用依据 [商家可见]、版本差异、发布检查 | 无可用知识阻断；必填缺失阻断；警告可继续 [R]；测试生成中/失败；发布中；发布成功；发布失败且线上不变 |
| 版本记录 | 了解和恢复线上版本 | 版本号/时间、操作者、变更摘要、回滚 | 首次无版本；当前正式；历史版本；回滚确认；回滚中/失败/成功 |
| 咨询列表 | 找到需处理会话 | 时间、客服、状态、未解决原因、是否有需求/联系方式 | 空；筛选无结果；加载失败；匿名且无联系方式；已暂停期间记录 |
| 咨询详情 | 理解上下文并跟进 | 原始消息、摘要、需求状态、版本、来源、反馈、跟进状态 | 消息加载失败；摘要未生成/失败；资料不足；技术故障；已删除/脱敏字段 [Q]；无访问权限 |
| 知识补充草稿 | 将问题转为可审阅知识 | 原问题、建议答案、事实字段、来源、适用条件 | AI整理中；待确认；缺少依据；保存草稿；放弃；并发修改冲突 |
| 账号与服务 | 管理商家和服务边界 | 商家资料、联系渠道、额度/用量、数据策略 | 额度正常/临近/耗尽；渠道未配置；策略未确认；保存失败 |

## 7. 核心对象及产品状态机

### 7.1 客服与发布状态

```text
未创建
  → 草稿不完整
  → 草稿可测试
  → 发布检查通过
  → 发布中
  → 已发布
        ├─ 编辑后：已发布 + 有未发布变更
        ├─ 紧急操作：已暂停 → 已恢复
        └─ 选择历史版本：回滚中 → 已发布（历史Release重新成为当前激活版本）
```

- 发布失败回到“草稿可测试/检查未通过”，既有线上版本保持服务。
- 暂停是独立于草稿/版本的服务状态，对所有Session立即生效 [R]。
- “没有线上版本”和“线上已暂停”在消费者提示与商家行动上必须区分。

### 7.2 知识状态

```text
草稿 → 待处理 → 处理中 → 可用于草稿 → 已随版本发布
                     └→ 失败 → 重试/替换
可用于草稿/已发布 → 已修改（新草稿）→ 重新处理
已发布 → 标记删除（新草稿）→ 新版本发布后不再检索
```

“冲突、过期、缺少条件”属于质量标记，不应与异步处理状态混为一个字段；是否阻断发布由规则评审决定 [Q]。

### 7.3 Session状态

```text
创建 → 有效/活跃 → 主动结束
               ├→ 超时失效 [时长Q]
               ├→ 因新建咨询结束
               └→ 因强制策略结束 [是否开放Q]
```

- 暂停客服不会让Session跨租户或跨版本迁移；恢复后的处理策略需与版本策略一致。
- “会话已结束”“历史记录是否保留展示”“后端数据何时删除”是三个独立概念。

### 7.4 消息状态

```text
本地待发送 → 提交中 → 已接收 → 回复生成中 → 已完成
                  └→ 发送失败（可用同一请求标识重试）
                           回复生成中 → 中断/失败（不得伪装完成）
```

同一Session的消息按顺序处理；当上一条仍在生成时，[R] 建议禁止再次发送并提示“当前回复完成后可继续”，是否允许排队属于 [Q]。

### 7.5 需求记录与跟进状态

```text
会话内收集中 → 待消费者确认 → 提交中 → 已登记
                                         → 提交失败（可重试）
已登记 → 待处理 → 处理中 → 已处理 [R]
```

需求提交状态和商家跟进状态分开；“已登记”不代表商家已查看，“已处理”也不代表业务交易成功。

### 7.6 Skill首次生成workflow状态

```text
未开始
  → 待身份连接
  → 收集行业
  → 收集业务资料
  → 收集价格/特殊策略
  → 补充缺失项
  → 待预览确认
       ├→ 修改：返回对应收集步骤（revision + 1）
       ├→ 暂停：可恢复 [保留策略Q]
       ├→ 取消：cancelled（不可直接继续写入）
       └→ 明确确认：creating → completed
                              ↘ failed_recoverable
```

同一用户可存在历史workflow，但 [R] 同一商家同一入口只允许一个`active/paused`首次生成流程，避免重复草稿。`completed`只表示客服草稿创建成功；发布是独立状态机和独立确认。

## 8. 内容与交互准则

### 8.1 风险文案词汇

| 场景 | 推荐表达 | 禁止/避免表达 |
| --- | --- | --- |
| 无报价依据 | “目前资料不足，暂时无法确认价格。” | “大概是……”后给无依据价格 |
| 无实时库存 | “页面没有实时库存信息，建议联系商家确认。” | “有货”“已为你保留” |
| 无预约系统 | “可以先登记你的时间偏好，由商家确认。” | “已经预约成功” |
| 需求提交成功 | “需求已登记，商家可根据你提供的联系方式跟进。” | “商家已接受”“服务已安排” |
| 联系渠道 | “拨打商家电话 / 添加企业微信 / 提交留言” | “已转接人工”（无坐席时） |
| 模型故障 | “当前服务暂时异常，请稍后重试或联系商家。” | 生成一个看似正常的业务结论 |
| Session过期 | “已开始新的咨询，之前的信息不会自动带入。” | 静默丢失上下文或暗示仍记得旧信息 |

### 8.2 可访问性与易用性

- 状态不能只靠颜色表达；错误、处理中、成功均配合文字和图标。
- 关键点击目标适合单手操作，输入框、发送按钮与底部安全区不冲突。
- 流式消息更新避免频繁抢夺焦点；屏幕阅读器应能识别消息角色与完成状态。
- 时间、版本、额度和适用条件使用明确单位；价格内容不得省略条件。
- 二次确认只用于有明显后果的操作，普通保存采用自动保存或轻提示 [R]。

### 8.3 Skill提问与帮助文案准则

- 开场直接给出两个入口，不使用“请描述你的全部需求”作为唯一提示。
- 一轮只问一个主题；同一主题可用紧凑字段清单，避免连续十几个零散问题。
- 每个问题说明“为什么需要”和“可以暂时跳过吗”，对价格/优惠给出带条件的示例但不暗示商家照抄示例值。
- 区分“暂无/没有”“不知道”“稍后补充”和“未回答”；只有“确认暂无”可以成为商家事实。
- 预览中把用户事实、系统整理建议、缺失项和即将执行的动作分区，不用一段自然语言混在一起。
- 所有成功文案指明真实结果层级，例如“草稿已创建，尚未发布”；返回管理链接不写成“你的客服已上线”。
- 身份提示统一使用：“请在打开的平台页面完成登录或授权。不要在对话中发送密码、验证码或Token。”

## 10. 可执行验收映射

### 10.1 执行前提

- 使用至少2家商家（M1、M2）、每家至少2名匿名访客（V1、V2）和多组Session。
- 准备一组有明确价格条件的知识、一组缺失价格的知识、一组相互冲突或过期的知识、一份不可解析文件。

| A04 范围与资料不足 | H5聊天、未解决记录 | Given 配置允许范围且知识无报价依据；When 分别询问越界问题和具体报价 | 越界问题被引导回业务；报价问题不编价/不承诺；商家侧可见对应未解决原因 | 事实边界 [M]；记录方式 [R] |
| A05 连续上下文 | H5聊天、需求状态 | Given 同一Session先说“两台挂机清洗”；When 再问“周六呢” | 回复仍关联清洗与两台；不重复询问已给字段；不把营业时间推断为可预约名额 | Session连续性 [M] |
| A06 同商家不同访客 | 两个匿名浏览器上下文、咨询详情 | Given M1下V1提供数量/地址；When V2发起咨询并请求相关信息 | V2的回复、摘要、需求字段和商家侧对应会话均不含V1信息 | 隔离要求 [M] |
| A07 跨商家隔离 | H5、管理端、接口错误页 | Given 已有M1会话；When 替换为M2公开标识或伪造session_id访问 | 不返回M1消息/知识/摘要；仅凭公开标识或session_id不能授权；管理端也不能跨商家读取 | 隔离要求 [M] |
| A08 刷新与新咨询 | H5恢复、新建咨询、超时提示 | Given 有效Session已有需求字段；When 刷新、主动新建、达到已确认超时时长后再发送 | 刷新恢复有效会话；主动新建经确认后不继承旧需求；超时后明确提示新咨询且不带旧需求 | 刷新/新建 [R]；超时时长 [Q] |
| A09 版本更新 | 测试发布、版本记录、两组Session | Given S1建立于V1后发布V2，再建立S2；When 两会话询问变更知识 | S2使用V2；S1按已确认版本策略处理；H5链接不变；商家详情可追溯各Session版本 | 固定链接 [R]；旧Session策略 [Q/R] |
| A10 需求与联系 | 需求确认、咨询详情 | Given 消费者填写需求并连续点击/重试提交；When 请求成功且商家未配置坐席 | 只产生1条需求；成功文案仅表示已登记；不显示转接成功；未提供联系方式时保持匿名 | 最少收集 [R]；渠道 [Q] |
| A11 异常与暂停 | H5系统状态、商家服务状态 | Given 分别模拟模型超时、额度不足、商家暂停；When 消费者发送消息 | 每种情况显示可理解且可区分的提示；不产生虚假业务答复/成功状态；暂停对所有Session立即生效 [若基线获批] | 异常诚实 [M/R]；配额 [Q] |
| A12 Skill闭环 | WorkBuddy与平台状态 | Given 已验证的目标WorkBuddy环境和测试商家；When 分别走“首次生成”和“已有客服”入口，再继续修改、测试、按明确指令发布并关闭WorkBuddy | 首次入口分步收集行业、业务资料和价格/优惠策略，缺失项可追问/跳过，确认后只创建一次草稿并返回受保护管理链接；已有入口只依据受控身份返回有权访问的后台；对话不收集密码；发布后H5可访问且WorkBuddy关闭后仍可用；失败不返回虚假链接 | 产品方向 [M]；接入可行性 [Q] |
| A13 重试与并发 | H5消息、需求提交、用量记录 | Given 同一请求标识重复发送，且同Session快速连续触发请求；When 服务端处理 | 不重复写消息/需求/记账；消息顺序稳定；进行中交互符合已确认的禁止发送或排队策略 | 一致性基线 [R]；排队UX [Q] |
| A14 权限与指令攻击 | H5、商家端、运营审计 | Given 消费者在聊天中要求改配置/给密钥/跨商家读取，或调用管理接口；When 请求执行 | 聊天不能触发管理写操作；不返回密钥或私有数据；接口拒绝未授权操作；受控运营访问有审计 | 安全边界 [M/R] |

## 11. 原型与后续设计输入

在D01—D23中与当前阶段相关的决策完成后，可按以下顺序继续细化：

1. 低保真原型：商家首次创建与发布、消费者连续咨询、商家查看未解决问题三个闭环。
2. 字段字典：配置、知识、需求收集、联系渠道、筛选项与校验规则。
3. 内容设计：AI身份、资料不足、越界、暂停、额度不足、Session失效和需求登记文案。
4. 权限与审计清单：每个页面/动作的主体、资源范围、敏感字段和审计事件。
5. 设计验收用例：将A01—A14及UX01—UX08补充为测试数据、浏览器矩阵和明确参数。

在未完成相应决策前，原型可以使用本文的 [R] 建议作为演示默认值，但必须保留标签，不能在交付物中改写为已承诺需求。
