# H5 AI客服生成与管理平台：设计分工

## 本轮目标

本轮只完成项目分工和设计基线，不进入功能编码。需求文档中的内容按以下状态管理：

- **已明确**：直接进入设计约束和验收映射。
- **建议基线**：作为首版设计默认值，仍需产品评审确认。
- **待确认**：保留决策点、默认建议和影响分析，不视为承诺功能。

## 协作规则

1. 所有设计以“商家级知识共享、消费者会话隔离”为首要约束。
2. 公开客服标识只能定位客服，不能作为会话或数据读取凭据。
3. 草稿与线上发布版本分离；固定H5地址不随发布改变。
4. 商家事实必须有可追溯依据，模型不得补造价格、库存、预约、订单或退款结果。
5. P0优先采用可在4至7周内形成小规模试用闭环的方案，结构上预留P1扩展，但不提前建设P2复杂度。
6. 所有写操作考虑幂等，所有租户数据访问同时校验身份、商家、客服、Session或版本归属。
7. WorkBuddy Skill是平台API的受限调用方，不承载在线消费者会话，也不假设其订阅额度可供外部服务使用。

## 总体任务的裁决职责

- 处理前端、后端、平台设计之间的接口和技术栈冲突。
- 将建议基线与已确认要求分开记录。
- 给出模块化单体与后续服务拆分边界，避免首版过早微服务化。
- 将A01至A14验收项映射到系统模块和测试层级。
- 输出可继续细化为原型、接口契约、数据库迁移和开发任务的统一设计。
