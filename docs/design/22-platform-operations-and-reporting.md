# 运营后台增强与报表口径

本轮增强围绕三个运营问题展开：哪些商家已经开始使用、哪些商家需要协助、哪里出现了失败。保留现有单运营账号和多商家隔离，在真实 MySQL 数据上增加平台总览、商家管理、商家使用详情与五类报表，不引入新的云资源或模型调用。

## 竞品参考

调研日期为 2026 年 10 月 18 日。下表描述公开官方材料提供的能力，不代表已登录体验其付费后台。竞品面向企业客服团队的分析模式用于本平台运营设计，不能把它们的客户指标直接当作本平台的商家指标。

| 产品 | 官方资料可确认的能力 | 本项目采用的设计 |
| --- | --- | --- |
| Zendesk AI agents | 按日期、客服等属性筛选，支持不同聚合视图与 CSV 导出。 | 报表独立入口、日期及商家筛选、同口径导出。 |
| Intercom Fin | 将回答、解决、升级和体验指标分别报告，并区分确认解决与推定解决。 | 将问句处理完成率与真实解决率明确区分；尚无用户反馈的数据不冒充解决率。 |
| Tidio | Analytics API 提供只读会话、评价、Lyro 线程和日汇总端点。 | 运营统计采用只读汇总查询，不为看报表触发业务写入或模型分析。 |
| Chatbase | 分析页提供会话情绪及话题趋势。 | 为话题及反馈分析保留后续扩展方向；本轮不额外发送消费者正文给模型。 |
| 晓多 | 接待工作台提供今日数据、团队与客服工作量、响应及评价统计，并支持导出。 | 将总览、商家／客服明细及异常分布分层，管理动作与统计分开。 |

来源：[Zendesk 报表操作](https://support.zendesk.com/hc/en-us/articles/9510024609178-Working-with-the-AI-agent-analytics-dashboards)、[Intercom Fin 报告](https://www.intercom.com/help/en/articles/7837533-fin-ai-agent-reporting)、[Tidio Analytics API](https://developers.tidio.com/docs/enable-analytics-api)、[Chatbase 分析更新](https://www.chatbase.co/changelog/improved-chatbot-analytics)、[晓多接待工作台操作手册](https://www.xiaoduoai.com/blog/docs/pwycuthimz5bz7wn)。

## 页面与权限

以下为同域名部署下的路径；本地无前缀模式由 Next.js 自动处理。

| 入口 | 内容 |
| --- | --- |
| `/ops` | 当前全平台商家及客服总数、期间使用概况、问句趋势；保留商家开通、行业模板、任务与审计。 |
| `/ops/merchants` | 商家名称／完整 ID 搜索，状态与期间使用筛选，稳定排序、分页、导出。 |
| `/ops/merchants/{merchantId}` | 商家当前状态、开通时间、最近消费者问句、期间用量、每日明细、客服使用、改进复测、领取／暂停／恢复操作。 |
| `/ops/reports` | 每日使用、商家使用、客服使用、改进与复测、异常分布。 |
| `/ops/reports/export` | 运营鉴权后的 CSV 下载；无运营会话返回 401。 |

所有页面先校验运营会话再查询数据。商家会话、消费者会话都不能替代运营会话。后台列表与商家详情只展示运行元数据及汇总，不展示消费者正文、手机号、密钥或登录凭据。运营看到商家后台链接不等于可以代登商家。

商家暂停／恢复沿用原有确认、原因、行锁、事务及审计机制。暂停不删除历史用量，不能通过筛掉已暂停商家来美化失败率。新界面没有批量删除、账号重置、强制代登或自动恢复入口。

## 统计口径

日期为北京时间自然日，区间两端日期均包含，最长 93 天，不允许未来日期。转换为 UTC 后使用左闭右开的 SQL 条件；参数传入 UTC 字符串，不依赖应用或数据库客户端所在时区。当天数据是查询时已入库的部分数据。

| 指标 | 定义与边界 |
| --- | --- |
| 累计商家 | `merchant` 全表计数，不是最近 50 条列表的长度，不受所选日期影响。 |
| 已启用、等待领取、已暂停 | 查询时商家账号状态；不是在线状态或期间活跃人数。 |
| 客服总数、已发布客服 | 当前客服记录数；已发布须为 `active` 且具有当前发布 ID。它不是实时服务健康检查，也不代表所属已暂停商家可以继续接待。 |
| 期间使用商家 | 期内至少提交一条 `role=visitor` 消息的不同商家；失败问句也表示有使用行为。 |
| 新建消费者会话 | `conversation_session.created_at` 落入区间的会话数，不等于独立消费者人数。 |
| 消费者问句 | `message.role=visitor` 且接收时间落入区间。只数消费者消息，不把 AI 回复再加一遍。旧会话的新问句按新问句接收日期计数。 |
| 完成、失败、未终结 | 入选问句在查询时的状态；当前非 `completed/failed` 的问句归入未终结。状态变化会回写其接收日期对应的历史统计，不是不可变日结账。 |
| 问句处理完成率 | 完成÷（完成＋失败）。未终结不进入分母，无终结样本显示“—”，不是 100%。不代表答案正确、消费者满意或问题解决。 |
| 平均处理耗时 | 对具有有效完成时间的完成问句，平均接收到完成的毫秒差；包括排队，不是首字延迟。无样本显示“—”。 |
| 最近消费者问句 | 商家全部历史的最后一条消费者问句时间，不受所选区间限制。 |
| 改进任务与发布 | 按任务创建日期入选；当前任务版本与已关联发布版本匹配才算“当前任务版本已发布”。 |
| 复测与评审 | 按复测创建日期入选，重复运行分别计次；完成、失败、待完成与商家通过、不通过、未评审分列。历史评审不等于仍可发布，也不是模型准确率。 |
| 异常分布 | 期内创建、当前失败的消费者问句按错误码分组；后台任务按类型及错误码单列。同一故障可同时产生两类记录，不能简单相加。页面最多显示前 50 组，导出最多 5,000 组。 |

公开 H5 发起的合成测试咨询仍会进入消费者用量，因为当前表没有可靠的测试流量标记。发布前试聊、资料撰写与独立复测不会作为消费者问句计入本报告。满意度、真实解决率、成交额、Token 与模型费用尚未采集，本轮不显示推测值或伪造的零值。

## 数据实现

新增 `MySqlPlatformAnalyticsRepository`，不变更表结构，不运行迁移。每次结果在短连接的 `REPEATABLE READ, READ ONLY` 事务内读取，单条 SELECT 限时 8 秒。各业务表先按商家或商家与客服聚合，再关联，避免会话、消息和客服之间的扇出重复计数。

商家及客服默认每页 20 条，商家详情最多展示前 50 个客服并提供完整分页入口。商家查询支持字面量名称匹配，`%`、`_`、`!` 被转义，完整 ID 使用二进制参数精确匹配。状态和排序采用白名单，ID、日期、页码均在查询前校验。日期汇总补齐零使用日；连接故障单独显示“统计暂不可用”，不能伪装成空列表或 0。

该实现面向当前单机受控试运行规模。历史消息量增长后，应根据真实查询计划增加索引或日汇总，不以本轮少量数据测试宣称达到大规模 SaaS 容量。

## CSV 导出

导出沿用当前区间、商家范围和列表筛选，不只导出当前一页。商家及客服最多 5,000 条，异常最多 5,000 组；超出返回 413，并要求缩小范围，不产生静默截断文件。日期范围外的新旧商家仍可出现在商家报表中，其期间用量可能为 0。

CSV 使用 UTF-8 BOM 和 CRLF，附带区间、时区、查询时间与商家范围列。引号、换行正确转义，公式前缀和长数字 ID 按文本保护。响应为私有、不缓存的附件，禁止跨站下载；无权限、无数据库或查询失败都不输出部分数据。

## 验证与发布

验证分为纯函数／SQL 边界单测、严格隔离数据库的真实 MySQL 聚合测试，以及原运营开通—商家发布—消费者对话浏览器用例的运营增强扩展。浏览器覆盖根路径、管理子路径和单域名模式，检查五种下载、权限隔离、商家详情及手机宽度布局。

上线前仍需完成项目现有 CI 和发布审核。本轮不自动合并主分支，不替换公网容器，不改变现有运营密码，也不恢复 WorkBuddy。具体测试结果以本分支验证记录和对应 CI 为准。
