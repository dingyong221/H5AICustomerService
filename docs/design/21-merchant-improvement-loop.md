# 商家持续改善首轮产品与数据设计

产品轮次 R1 候选；研发基线 `53172bd`，统一分支 `codex/merchant-improvement-loop`。依据见[竞品研究与路线](../product/continuous-product-research-2026-10-17.md)。候选功能的完成、实测和部署状态以验收记录为准。

## 产品目标和边界

商家从真实咨询出发，知道什么需要改、写清正确依据、验证当前草稿，再确认发布；下次仍能回看来源、测试答案和对应版本。消费者能获得合理回复和真实人工联系说明。

本轮不新增复杂 RAG、微服务、收费资源、自动学习、实时坐席或满意度统计。模型输出不是问题解决，默认 pending 跟进不是未解决率，资料确认不是质量保证。

## 页面和交互

| 页面 | 用户任务 | 下一步和错误反馈 |
| --- | --- | --- |
| `/{merchantId}` | 看真实改善待办及创建入口 | 空状态能开始；数字不是准确率 |
| `/{merchantId}/conversations/{sessionId}` | 从具体消费者问题建立任务 | 原问题、原回答、正式版本由数据库读取，原消息不可编辑 |
| `/{merchantId}/improvements` | 按客服查任务，也可手工录入场景 | 原因分缺资料、错误、政策不明、人工、投诉等；最近 50 条及完整数量明确区分 |
| `/{merchantId}/improvements/{id}?assistant={assistantId}` | 看来源、写期望答案、应用补丁、复测、人工判断和追溯发布 | 失败保留输入；stale 要求核对，不静默覆盖 |
| 草稿、知识页 | 维护真实商品、报价、活动、售后和人工说明 | 规则自检无评分；通用模板不是本店事实 |
| 测试与发布页 | 对照问题和验证状态，明确发布 | 失败或过期不算通过，一次发布不清空所有问题 |
| 消费者 H5 | 正常咨询、查看已发布的人工联系说明 | 无说明明确未设置，不称已转接或已提交 |
| 帮助中心 | 按任务查步骤及限制 | 页面与下载共用内容 |

## 业务规则

来源任务只接收本商家、本客服的 visitor 消息，原回答来自同一 turn 已完成回复。重复标记同一来源不重复建任务；手工场景和后续写入使用幂等键，同键不同内容拒绝。

问题、期望答案、备注分别最多 2000 字。期望答案应是已核对的事实及适用条件，不能虚构库存、价格或交易结果。投诉、人工任务改善的是答复和指引，不代表诉求结案；原咨询人工跟进独立处理。

应用前展示完整 FAQ 补丁并勾选事实确认。只修改当前未发布草稿的商品/服务资料，保留其他全文；合并后最多 4000 字，超长拒绝不截断。同任务二次修正替换自己的管理块；管理块被人工修改后拒绝自动覆盖，需人工核对。不同字段的矛盾政策不会自动消除，商家须同步修改原价格、优惠等字段，再复测。

应用需要任务版本及草稿修订同时匹配，生成新修订并取消原资料确认；不修改正式快照、公开链接和原咨询。

复测先持久化 pending，再由服务端调用现有 Worker，不能接受浏览器提交答案冒充模型结果。商家明确同意把当前草稿与原问题发送至阿里云千问。相同请求不重复调用；同任务同修订的活跃运行不重复计费，超过 120 秒保留中断记录后才允许新运行。模型调用不占长事务。

实际答案保存后是待审阅，商家明确 pass/fail。判定绑定任务版本、草稿修订、内容哈希、问题/期望快照、提示与模型策略版本。草稿或任务改变后，晚返回结果只作历史；当前最新失败或未审阅不能被旧通过覆盖。运行同毫秒时也须确定最新顺序。

只有精确有效测试的修订成功发布，才在同一发布事务内关联 release 并显示已上线。发布失败不关单，后来版本变化保留历史但不保证当前内容通过。首轮不以所有历史任务通过为正常发布的硬门槛，避免人工个案锁死已有业务；发布页明确显示待办与边界。

## 状态语义

| 状态 | 依据 | 商家下一步 |
| --- | --- | --- |
| 待修正 | 未保存答案或有效修正未进入当前草稿 | 核对并应用 |
| 待复测 | 缺测试，或任务、草稿、策略变化 | 复测当前修订 |
| 待审阅 | 当前实际答案已保存，尚无人工判定 | 阅读并判定 |
| 未通过 | 调用失败或人工判不合适 | 修正或显式重试 |
| 已验证待发布 | 精确修订人工通过，未关联当前 release | 确认资料再发布 |
| 已上线 | 有效通过对应当前正式版本 | 继续观察，不等于所有问题已解决 |

## 数据与兼容

增量迁移 `0012_chilly_talisman.sql` 只增加两张 InnoDB 表，不重写历史数据。

| 表 | 保存内容 | 约束 |
| --- | --- | --- |
| `assistant_improvement` | 租户/客服、版本、来源 session/message/release、原因、原问题/原答、期望、备注、管理块/修订、发布关联、人和时间 | 复合租户外键，同来源唯一，手工场景允许无来源 |
| `assistant_evaluation_run` | 租户/客服/任务、任务和草稿版本、哈希、问题/期望快照、实际答案/失败、策略、人工判定及时间 | 复合任务外键，追加历史，不将失败改成通过 |

人工联系说明为可选 `AssistantDraftConfig.humanContact` 纯文本，最多 500 字。旧草稿缺字段时不增加空 key，保持原资料确认哈希。新 release 才带新说明；旧会话继续读取原 release。文字不执行 HTML，不自动变成任意链接。

旧 H5 严格拒绝未知字段。新版请求以 `X-H5CS-Features: human-contact` 声明能力，API 只对已协商客户端返回新增字段；旧客户端仍收到旧集合，新 H5 可接受旧 API。内部 Worker 先兼容旧、新草稿，再切换依赖它的商家端。

## 权限和发布保护

MID、AID 和任务 ID 不是权限。页面复核成员；写入校验 Origin、作用域会话及 CSRF；事务再核对 active 商家、用户和成员。按统一客服锁顺序处理修订、幂等、任务与测试，不在模型等待时持锁。

先单元、真实隔离 MySQL、构建与浏览器，再做有限千问实测。服务器剩余约 3.3 GB，测试使用独立 tmpfs MySQL，不重复在生产构建全部镜像，不擅自删旧镜像和卷。

生产迁移和切换另备具体变更包、风险/备份引用和回退证据。代码回退保留新增表与历史；不 DROP 表回退。收费资源、公开数据库、MCP 上线和运营多账号不在本轮。

## 验收要求

1. 保温杯新疆运费：原咨询、标记、修正、原题复测、人工判定、确认发布、新会话生效；旧会话、原答和旧 release 不变。
2. 真 MySQL：租户/客服隔离、幂等、双版本并发、测试晚返回、失败和发布事务、增量迁移。
3. 二次修正不留旧错 FAQ，人工块改动不覆盖，4000 字不截断，表单失败输入仍在。
4. 真实模型覆盖型号不明、优惠条件、资料冲突、库存、投诉和人工；结果逐条人工评，不能用 mock 声称合理。
5. 桌面/手机入口、登录回跳、刷新持久性、空状态、错误、帮助与兼容。
6. 单独记录通过、失败、未测、未部署。旧线上测试不作为新版验收。
