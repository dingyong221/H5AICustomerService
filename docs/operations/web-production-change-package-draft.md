# Web 生产变更包草案

> 状态：准备中，不可执行。首次生产 Schema 迁移和公网业务切流需要**两次分别确认**。本文档不是变更授权，也不是通过发布门禁的证明。

本变更只覆盖 `h5cs.1rying.com` 的平台运营后台 `/ops`、商家后台 `/console`、消费者客服 `/a` 和业务 API `/api`。WorkBuddy、MCP、OAuth 和 Skill 不启用。当前现场证据见[发布盘点](2026-10-03-production-inventory.md)，通用停止与回滚规则见[发布与回滚 Runbook](release-and-rollback-runbook.md)。

## 分离的执行与授权检查点

1. **准备与冻结。** 核对 GitHub 远端 `main`、依赖审计、最终镜像签名和五摘要。把 Compose、Nginx 切流文件及其 `sha256sum`、环境文件权限、当前 503 路由和回滚文件记录进变更单。`/etc/nginx/sites-available/h5-ai-customer-service` 是目前的正式入口配置；切流前先复制并校验可恢复副本，不覆盖不明来源的旧备份。
2. **Staging。** 精确部署同一五摘要，完成运营开通 → 商家认领/配置/发布 → 消费者真实千问咨询；验证不同商家隔离、异步任务、SSE、文件处理、审计、TLS、异常处理及应用回滚。记录实际 URL、时间、构建提交和失败项。未通过时停止，不进入生产。
3. **迁移前停点。** 记录生产库当前表数、卷和备份哈希、恢复测试、容量、连接 TLS、迁移账号最小权限、最终 API 镜像的迁移清单及 `planSha256`。当前单机迁移 Compose 强制要求 `H5CS_MIGRATION_BACKUP_REF` 指向已验证离机备份；已接受的试运行风险不能伪装为此条件通过。必须先另行评审实现一个**不会伪造离机备份成功**的受控试运行路径。向项目负责人单独请求“执行首次生产数据库迁移”的明确授权；未获授权不运行 migrator。
4. **迁移执行。** 授权后按[单机 MySQL 记录](single-node-mysql.md)使用独立 `migrator` profile、最终 API 摘要、受限连接串文件、CA、目标主机 `mysql.h5cs.internal`、目标库和已复核计划哈希执行一次。只有输出明确的目标信息及 `MySQL migration completed`，并通过 Schema、租户和应用只读核验，才进入下一步。MySQL DDL 失败时不得盲目重试或“反向迁移”。
5. **公网切流前停点。** 再次核对实际五摘要、Worker 真实模型与密钥挂载、生产库状态、TLS、监控/人工巡检、Nginx 回退文件和前一步迁移结果。向项目负责人**另行请求**“开放公网 Web 业务入口”的当次授权；未获授权维持 `/ops`、`/console`、`/a`、`/api` 的 503。
6. **切流、验收与观察。** 授权后只更改本项目 Host 的业务路由，先 `nginx -t`，再受控重载。用公网真实 HTTPS 完成四路径的业务闭环和跨商家隔离；验证 MCP/OAuth/Skill 路径按 Web-only 策略明确拒绝。观察 5xx、延迟、Worker/Job、MySQL、磁盘与证书，并记录短期值班负责人和观察结束时间。
7. **回退与旧栈处理。** 应用回退使用本变更单记录的精确 previous 摘要和 Nginx 副本；先核对迁移后 Schema 兼容性。数据损坏或跨租户事件先停止写入、保存证据，再由事故负责人决定恢复，不自动切回。旧候选栈只在观察期结束、回滚目标另有可靠保存且用户单独授权后停止或移除。

最终执行命令、完整摘要、备份/风险接受引用、计划哈希和签字人必须在变更当天写入受限变更记录并复核；本草案故意不提供带占位参数、可被误运行的生产命令。
